# AI Maintenance Framework — 설치용 파일

공개 배포 버전 0.1.0 · 2026-10-12 · 한국어 기본형

목표는 다른 AI도 설계 의도를 이해하고, 계약과 데이터를 지키며 모듈을 수정하거나 교체할 수 있게 하는 것이다. 재생성 독립성은 설계 목표이며, 안전한 교체를 자동 보장하는 성질은 아니다.

**기본 정책: PATCH 우선 / 실용형 절차 / 위험한 변경은 검증 강화.**

## AI에게 적용을 맡기기

일반 사용자는 파일을 직접 편집할 필요가 없다. 저장소 루트의 [AI 적용 절차](../INSTALL.md)를 AI에게 읽게 하고 프로젝트 위치를 알려 준다. 아래는 AI와 직접 적용하는 개발자를 위한 순서다.

## 직접 적용 순서

1. [적용 가이드](APPLY.md)를 읽고 기존 지침과 충돌을 확인한다.
2. 프로젝트 루트에 `CLAUDE.md`, `AGENTS.md`, `.ai/`를 병합한다. 기존 파일을 덮어쓰지 않는다.
3. `.ai/PROJECT.md`에 실제 기술 스택, 명령, 데이터 소유권과 운영 제약을 채운다.
4. 변경할 첫 모듈의 계약을 `contracts/`에 작성한다. 템플릿은 `templates/`에 있다.
5. AI에게 [시작 프롬프트](PROMPTS.md)의 프로젝트 점검 또는 기능 변경 요청을 전달한다.

## 구성

| 경로 | 역할 |
|---|---|
| `CLAUDE.md` / `AGENTS.md` | 도구별 진입점 |
| `.ai/CORE.md` / `.ai/WORKFLOW.md` | 상시 규칙과 작업 진행 |
| `.ai/ARCHITECTURE.md` / `.ai/MODULE_BOUNDARY.md` | 구조·책임·데이터 경계 |
| `.ai/CONTRACT_FIRST.md` | 관찰 가능한 행동 계약 |
| `.ai/DATA_SAFETY.md` | 영속 데이터·마이그레이션 보호 |
| `.ai/VERIFICATION.md` / `.ai/REGENERATION.md` | 독립 검증과 PATCH/REBUILD 판단 |
| `.ai/PROJECT.md` | 프로젝트마다 채우는 설정 |
| `templates/` | 프로젝트·모듈·계약·변경·ADR·마이그레이션 양식 |
| `contracts/` | 모듈 계약 저장 안내 |
| `verification/` | 체크리스트와 실행 검증 연결 |
| `examples/typescript-postgresql/` | 운동 수업 예약 서비스의 가상 예시 |

핵심 원칙은 공통 문서가 단일 원본이다. 진입점은 문서를 읽는 순서만 안내한다. 프로젝트 설정과 계약을 업데이트하면 두 도구가 같은 기준을 따른다.

## 작동 범위

이 패키지는 지침과 템플릿이다. Markdown만으로 SQL 접근, 배포 또는 테스트 누락을 차단할 수 없다. [검증 장치 가이드](verification/GATES.md)에 따라 프로젝트의 린터·테스트·CI·DB 권한을 연결해야 한다. 빈 설정이나 예시의 테스트 시나리오는 실행 검증을 대신하지 않는다.

새 프로젝트에는 모듈러 모놀리스를 출발점으로 검토하고, 기존 프로젝트에는 현재 구조를 우선 존중한다. 헥사고날 구조와 계약 우선 개발은 유용한 수단이며 모든 함수에 인터페이스를 만드는 요구가 아니다.

도구별 로딩 근거와 설계 원칙의 출처는 [SOURCES.md](SOURCES.md)에 기록했다. 적용 후 지침 로딩은 각 도구의 새 세션에서 확인한다.
