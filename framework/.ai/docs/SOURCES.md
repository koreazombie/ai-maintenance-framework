# 출처와 설계 범위

## 설계 원칙

이 프레임워크는 기존 소프트웨어의 유지보수·리팩토링·모듈 교체를 AI가 수행할 때 사용할 작업 규칙을 제안한다.

- 업무 책임·변경 독립성·데이터 소유권·계약 안정성에 따른 모듈 경계
- 공개 행동 계약과 영속 데이터 보존
- 요구사항·불변조건에서 도출한 독립적인 검증 기준
- 모듈러 모놀리스와 필요한 경계의 포트/어댑터
- 작은 수정 우선, 근거와 준비 조건이 갖춰진 경우 내부 재생성

'재생성 독립성'은 이 프레임워크에서 내부 교체의 독립성을 설명하는 표현이다. 표준이나 안전 인증으로 주장하지 않는다. 특정 업체의 공식 아키텍처 방법론이 아니다.

## 도구별 로딩 — 2026-10-12 확인

- [OpenAI 공식 AGENTS.md 지침](https://learn.chatgpt.com/docs/agent-configuration/agents-md): Codex 지침 발견과 계층 적용. 공통 문서는 진입점의 지시에 따라 직접 읽는다.
- [Claude Code 공식 메모리 지침](https://code.claude.com/docs/en/memory): CLAUDE.md와 파일 가져오기. 공통 핵심 문서는 프로젝트 내 파일을 `@`로 가져온다.

위 출처는 로딩 방식의 근거다. 프로젝트의 데이터·아키텍처 정책 전체가 해당 업체의 공식 권고라는 뜻은 아니다. 실제 적용은 도구 버전·조직 설정에 맞게 확인한다.
