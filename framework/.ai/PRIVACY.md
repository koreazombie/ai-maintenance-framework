# 지침 공개·비공개 관리

선택 상태: 미선택 — 설치 시 사용자 선택을 기록한다.

## 방식

| 선택 | 프로젝트 Git | 다른 환경 |
|---|---|---|
| 함께 관리 | `.ai/` 포함, 저장소와 함께 공유 | Git 복제로 전달 |
| 로컬 비공개 | `.ai/` 제외 | 각 컴퓨터에서 재설치 또는 승인된 복사 |
| 비공개 별도 관리 | 프로젝트 Git에서 `.ai/` 제외 | 승인된 비공개 저장소/동기화 경로 사용 |

저장소가 지금 비공개라고 해서 앞으로 공개할 지침까지 자동 허가된 것으로 해석하지 않는다. 공개 여부가 미선택이면 AI는 필요한 조사와 계획부터 진행하고 설정 생성 전에 선택을 확인한다.

## 비공개 방식

프로젝트 루트 `.gitignore`에 다음을 병합하고 실제 제외 결과를 확인한다.

```gitignore
/.ai/
```

Git ignore는 이미 추적 중인 파일에 적용되지 않는다. 추적 파일은 목록·범위를 설명하고 허가된 추적 해제만 수행한다. 파일을 삭제하지 않고 로컬 내용을 보존한다. 이미 공개한 과거 커밋·다운로드·포크는 ignore나 추적 해제로 제거되지 않는다. 이력 재작성은 자동 수행하지 않는다.

`.ai/`가 다른 컴퓨터·작업 폴더·CI에 없으면 AI는 누락을 보고한다. 로컬 비공개 내용을 공개 이슈·PR 설명·로그로 복사하지 않는다. 제외된 파일을 force add하거나 관리 방식을 변경하려면 해당 요청의 범위를 확인한다.

## 두 진입점

공개될 수 있는 CLAUDE.md/AGENTS.md에는 일반 규칙·경로만 두고 내부 업무·운영 정보를 넣지 않는다. 이미 존재하는 프로젝트 지침은 사용자의 내용을 보존하면서 공개 범위를 검토한다. 전체 진입점을 감추고 싶은 경우는 별도 정책으로 관리한다.

## 모든 방식에 공통

비밀값·토큰·고객 데이터는 지침에 저장하지 않는다. 공개/비공개 구분은 이런 정보를 저장할 허가가 아니다. 프레임워크 지침 폴더와 제품 코드·실행 테스트·공개 API 스키마는 구분한다.

Git 동작 근거: [gitignore](https://git-scm.com/docs/gitignore), [git rm](https://git-scm.com/docs/git-rm).
