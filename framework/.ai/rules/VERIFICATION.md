# 독립 검증

독립성은 같은 AI가 작성한 테스트를 금지한다는 뜻이 아니다. 정답의 근거와 검증 경로가 새 구현의 내부 계산에 종속되지 않도록 하는 것이다. 다른 AI의 찬성만으로 검증을 대체하지 않는다.

## 정답의 근거

우선순위는 합의된 요구사항·업무 불변조건 → 승인된 계약 → 확인된 기존 소비자 기대 → 관찰된 기존 행동이다. 서로 충돌하면 사실과 미확인 규칙을 분리한다. 기대값을 새 구현의 helper로 계산하지 않는다.

## 위험에 맞춘 검증

| 수준 | 예 | 필요한 증거 |
|---|---|---|
| 낮음 | 문구·스타일·동작 없는 정리 | 관련 빌드/정적 검사 또는 직접 확인; 불필요한 신규 테스트 생략 |
| 보통 | 기능·버그·공개 행동 변경 | 재현/수용 시나리오, 관련 회귀, 계약·경계 확인 |
| 높음 | 결제·권한·데이터·동시성·REBUILD | 보통 수준 + 실제 인프라 통합, 실패·경쟁·호환성·복구 검증 |

구체적 위험을 기준으로 분류한다. 코드 줄 수가 작아도 권한 조건 한 줄은 고위험일 수 있다. 실행 환경이 없으면 준비 가능한 검증은 수행하되, 고위험 적용 준비가 끝났다고 보고하지 않는다.

## 서로 다른 오류를 잡는 검사

- 도메인 테스트: 불변조건과 상태 전이. 구현 구조를 그대로 복제하지 않는다.
- 계약/소비자 테스트: 공개 진입점에서 입력·출력·오류·부작용 확인.
- 통합 테스트: 실제 사용하는 DB·외부 연결의 트랜잭션·제약·실패 확인. mock만으로 DB 원자성을 주장하지 않는다.
- 경계 검사: import 방향·공개 진입점·데이터 접근 위반 확인.
- 중요 흐름 테스트: 사용자의 핵심 시나리오와 권한 거절.
- REBUILD 검증: 구/신 구현에 동일 계약 시나리오 적용, 차이를 분류, 기존 데이터 fixture와 소비자 확인. 기존 버그는 합의된 정답으로 따로 판정한다.

정적 검사나 타입 검사 통과는 의미적 호환성의 증거가 아니다. 커버리지 숫자만으로 완성을 판단하지 않는다. 추가 검증은 남은 위험을 줄이는 경우에만 넓힌다.

## 증거 기록

실행 명령, 환경(비밀 제외), 코드 기준점, 결과, 미실행 이유를 남긴다. `.ai/verification/CHECKLIST.md`의 N/A는 사유를 적는다. 적용 가능한 필수 검사 실패/미실행이 남으면 '완료' 대신 '로컬 구현 완료, 적용 검증 미완료' 등 정확한 상태를 사용한다.

테스트·계약·게이트를 수정했다면 구현과 별도로 변경 이유와 검증 약화 여부를 검토한다. 테스트를 지우거나 skip해서 녹색 상태를 만들지 않는다. 정당한 폐기·변경은 근거와 대체 증거를 기록한다.
