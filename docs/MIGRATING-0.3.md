# v0.2.0 → v0.3.0 프로파일 이전

실제 프로젝트는 자동 업데이트되지 않는다. AI가 현재 내용을 조사하고 기존 프로파일/관리 선택·사용자 설정·미커밋 변경을 보존한다.

1. 기존 프로젝트 규모·위험을 조사해 solo 또는 modular을 선택한다. 줄 수·개발자 수만으로 결정하지 않는다.
2. 지침 관리 선택을 shared/local-guidance/private-sync/local-all 중 확인한다. 진입점까지 감추는 local-all도 독립 선택이다.
3. modular은 기존 `.ai/` 설정·계약을 병합하고 버전·프로파일·관리 선택 필드를 맞춘다. 새 원본 규칙과 검사기를 설치한다.
4. solo로 축소하면 세 지침만 남기는 계획을 제시한다. 기존 modules·계약·작업 기록·사용자 규칙을 임의로 지우지 않는다. 승인된 비공개 외부 보관 또는 현 프로파일 유지 중 선택해 보존한 뒤 불필요한 프레임워크 파일을 정리한다. 제품 문서·코드·테스트는 이동하지 않는다.
5. 두 진입점의 가져오기는 선택한 프로파일의 필수 세 문서를 기준으로 맞춘다. 기존 팀 지침과 다른 상위 지침은 보존한다.
6. 선택한 파일·라이선스·검사기만 설치하고 release catalog를 확인한 뒤 record_installation으로 기준을 기록한다. 기존 기준은 검토한 변경에만 --refresh로 갱신한다.
7. 설치 검증기를 실행하고 placeholder·버전/파일 해시·프로파일·관리 방식·실제 Git 상태의 실패를 해결한다. 미확인 사실은 경고로 남겨 설명한다.

비공개로 선택한 기존 추적 파일은 영향·권한 범위에 따라 추적 해제하며 실제 파일은 보존한다. 과거 공개 이력 재작성은 별도 작업이다. 개인정보·비밀·계약 내용을 공개 PR/로그에 옮기지 않는다.

원본 규칙에 사용자 수정이 있다면 별도 보존·비교 후 원본/프로젝트 예외로 구분한다. 검사를 통과시키기 위해 무조건 해시를 갱신하지 않는다.
