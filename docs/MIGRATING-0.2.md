# v0.1.0 → v0.2.0 이전

실제 프로젝트에서 AI가 수행하는 보존·병합 절차다. 공개 저장소 업데이트가 설치된 프로젝트를 자동 변경하지 않는다. 먼저 지침 관리 방식을 확인하고 제품 코드는 유지한다.

| 기존 프레임워크 생성 경로 | 새 위치 |
|---|---|
| `.ai/CORE.md` 등 공통 규칙 8개 | `.ai/rules/` |
| `.ai/PROJECT.md`, `.ai/FRAMEWORK.md` | 기존 위치 유지 |
| 프레임워크용 `templates/` 파일 | `.ai/templates/` |
| 프레임워크용 모듈 설명·계약 | `.ai/modules/<module>/` |
| 프레임워크용 `verification/` 문서 | `.ai/verification/` |
| 프레임워크용 변경·ADR·인계 기록 | `.ai/changes/` |
| 프레임워크 사용 안내 | `.ai/docs/` |
| 프레임워크 참고 예시 | `.ai/examples/` |
| 원본 MIT 고지 사본 | `.ai/LICENSE` |

1. 미커밋 변경·현재 내용·이동 대상을 확인하고 기존 버전의 기준점 또는 승인된 백업을 보존한다.
2. 이름만 보고 루트 templates/contracts/verification/docs 전체를 이동하지 않는다. 실제 제품 파일·실행 테스트·OpenAPI 등 스키마·사용자 작성 문서는 기존 위치를 유지한다. 출처·내용이 모호한 파일은 확인한다.
3. 프레임워크가 생성한 문서만 이동·병합한다. 대상 파일이 있으면 양쪽 내용을 보존하고 충돌을 해결한다. 기존 커스텀 업무 규칙과 계약을 신규 빈 양식으로 덮어쓰지 않는다.
4. 루트 두 진입점, 모든 문서 링크·경로·Claude 가져오기·참조하는 도구 설정을 수정한다. 대소문자도 실제 파일과 일치시킨다.
5. `.ai/PRIVACY.md`에 선택을 기록한다. 비공개 방식이면 실제 ignore·추적·스테이징 상태를 확인한다. ignore만 추가해 이미 추적된 내용을 숨겼다고 보고하지 않는다.
6. 추적 해제가 필요하면 정확한 파일 범위와 영향·과거 공개 상태를 설명하고 허가된 변경만 한다. `git rm --cached`는 로컬 파일 보존을 전제로 검토할 수 있다. 전체 폴더 삭제·강제 제거·이력 재작성·force push는 자동 수행하지 않는다.
7. 이동된 원본 문서와 새 문서의 내용 보존, 제품 파일 미변경, 모든 경로·가져오기와 지침 로딩을 검증한다. 중복 복사본을 제거할 때도 원본·대상 일치와 사용자 변경을 먼저 확인한다.
8. 버전·원본·관리 방식·이동 내역·남은 예외를 `.ai/FRAMEWORK.md`에 남긴다. 비공개 파일의 내용을 공개 PR·로그에 붙이지 않는다.

로컬 비공개 방식에서는 Git만으로 `.ai/` 내용을 복구할 수 없으므로 복사/복구 경로를 확보한다. 다른 컴퓨터에서는 별도 재설치·동기화가 필요하다. 기존 공개 이력 삭제는 이번 이전의 자동 작업 범위가 아니다.
