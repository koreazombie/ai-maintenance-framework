# 설치 검증이 확인하는 것

배포 자체는 check_package.py와 generate_catalog.py --check로 검사한다. 사용자 프로젝트의 설치 상태는 설치된 `.ai/tools/validate_installation.py`가 검사한다.

- PROJECT.md의 `<...>`, TODO/TBD/PLACEHOLDER, 미설정·미선택 같은 미완성 값.
- 버전·프로파일·관리 선택과 실제 선택 파일 목록.
- 원본 규칙·검사기·라이선스가 해당 릴리스의 해시와 같은지.
- 사용자 설정/병합 진입점이 검토·기록한 해시와 같은지.
- modular의 FRAMEWORK.md 버전과 JSON/catalog/검사기 버전 일치.
- solo에 모듈형 지침·폴더가 잘못 남았는지.
- 진입점 가져오기 대상 존재와 선택한 Git 공개·비공개 상태.

`installation.json`은 현재 설치 기준, `release-catalog.json`은 배포 원본의 프로파일/해시 목록이다. 사용자가 의도적으로 PROJECT나 진입점을 바꾸면 AI가 내용을 검토한 뒤 원본 저장소의 record_installation.py --refresh로 기준을 갱신한다. 원본 규칙 변경이나 버전 오류를 정상 상태로 등록하지 않는다.

이 방식은 누락·실수·버전 혼합·기록 뒤 변경을 탐지한다. 파일과 catalog를 함께 악의적으로 조작하는 공격을 막는 서명 체계가 아니다. AI가 작성한 산문의 진실, 존재하는 명령의 실제 실행 성공, 제품 데이터 정합성, 과거 공개 이력 삭제는 확인하지 않는다.

'미확인: 이유'는 검사 경고다. 필요 없는 항목을 솔로에 생성하지 않는다. Git이 없거나 접근할 수 없으면 Git 검증 미실행을 경고하며 실제 비공개 완료로 해석하지 않는다. 제품 테스트와 CI는 별도 검증 경로다.
