# AI Maintenance Framework

**AI에게 기존 코드의 기능 추가·삭제·수정과 리팩토링을 맡길 때 사용하는 공통 작업 규칙입니다.**

사용자는 원하는 변경을 설명합니다. AI는 프로젝트를 조사하고, 기존 동작과 데이터를 보호하면서 작업하도록 지침을 적용합니다. 사람이 작성한 코드와 AI가 작성한 코드 모두에 사용할 수 있습니다.

한국어 기본형 · 공개 배포 버전 **0.3.0** · [MIT License](LICENSE)

## 바로 사용하기

저장소 주소: [koreazombie/ai-maintenance-framework](https://github.com/koreazombie/ai-maintenance-framework)

아래 적용 요청문의 `<프레임워크 위치>`에 위 주소를 넣으세요.

프로젝트를 작업하는 AI에게 아래를 전달하세요. `<프레임워크 위치>`에는 이 저장소의 주소나 다운로드한 폴더 위치를 넣습니다. `<내 프로젝트 위치>`도 실제 위치로 바꿉니다.

```text
<프레임워크 위치>의 AI Maintenance Framework를
<내 프로젝트 위치>에 적용해 줘.
먼저 INSTALL.md를 읽고 실제 프로젝트를 조사해 설정해 줘.
기존 지침과 내가 수정 중인 파일은 보존해 줘.
이번에는 프레임워크 설정만 진행하고 제품 코드는 바꾸지 마.
적용한 내용과 내가 결정해야 할 업무 규칙을 쉽게 설명해 줘.
```

AI가 주소의 파일을 읽을 수 없다면 저장소를 다운로드하고 폴더 위치를 알려 주세요. 프로젝트 코드에 접근할 수 없는 일반 대화에서는 실제 파일 적용이 불가능합니다. 코드에 접근할 수 있는 개발 도구에서 사용하세요.

설치 중 AI가 지침을 공개 코드와 함께 관리할지, 로컬 또는 별도 비공개로 관리할지 확인합니다. **진입점까지 제외하는 로컬 비공개(진입점 포함)**도 선택할 수 있습니다. 공개 저장소에서도 지침은 비공개로 유지할 수 있습니다. 선택하면 관련 설정을 AI가 처리합니다.

프로젝트를 조사해 **스크립트/솔로** 또는 **앱/모듈형** 프로파일을 고릅니다. 솔로는 PROJECT.md·CORE.md·WORKFLOW.md 지침 세 개만 설치합니다. 구조·DB·모듈 계약 문서를 먼저 깔고 해당없음으로 채우지 않습니다.

아래는 앱/모듈형 구조이며 솔로에는 그중 세 지침과 버전 기록·검사기·라이선스만 설치합니다.

```text
프로젝트/
  CLAUDE.md
  AGENTS.md
  .ai/
    rules/
    modules/
    templates/
    verification/
    changes/
    PROJECT.md
    FRAMEWORK.md
    PRIVACY.md
    LICENSE
    installation.json
    release-catalog.json
    tools/validate_installation.py
```

프레임워크가 생성하는 문서는 `.ai/`에 모읍니다. 제품 코드·실행 테스트·공개 API 스키마는 기존 위치를 유지합니다. Git에서 제외한 `.ai/`는 다른 컴퓨터에 따로 설치하거나 동기화해야 합니다.

적용한 뒤에는 평소처럼 요청합니다.

```text
예약 취소 기능을 추가해 줘.
프로젝트 개발 지침에 따라 작업하고,
기존 기능과 데이터에 문제가 없는지도 확인해 줘.
끝나면 변경 내용과 확인 결과를 쉽게 설명해 줘.
```

사용자는 Markdown 파일을 직접 작성할 필요가 없습니다. AI가 조사와 설정을 담당합니다. 다만 예약 취소 시 횟수를 복구할지 같은 업무 결정은 질문할 수 있습니다.

## 무엇에 쓰나요?

| 작업 | 사용 방식 |
|---|---|
| 기능 추가·수정 | 관련 코드와 기존 연결을 확인한 뒤 필요한 범위만 변경 |
| 기능 삭제 | 호출자·데이터·외부 연결을 확인하고 호환성과 데이터 보존 처리 |
| 버그 수정 | 기대 동작과 재현 조건을 확인하고 회귀 검증 |
| 리팩토링 | 외부 동작을 유지하며 내부 구조 개선 |
| 모듈 재생성 | 계약·데이터 호환성·검증·복구 조건을 갖춘 뒤 내부 교체 |

언어와 프레임워크를 고정하지 않습니다. Java/Spring, Python, TypeScript 등 프로젝트의 실제 구조와 도구에 맞춰 설정합니다. TypeScript/PostgreSQL 예시는 참고용입니다.

현재의 중심은 **기존 프로젝트 유지보수와 리팩토링**입니다. 신규 개발의 구조 원칙은 포함하지만, 아이디어에서 첫 서비스를 만드는 전체 안내는 아직 제공하지 않습니다.

## 기본 원칙

- 작은 수정부터 선택하고, 필요성과 준비가 확인되면 모듈을 교체합니다.
- 다른 기능이 사용하는 약속과 영속 데이터를 보존합니다.
- 검증 결과를 정직하게 보고하고, 테스트를 약화해 통과시키지 않습니다.
- 작은 작업은 간단히, 데이터·권한·결제처럼 위험한 작업은 더 꼼꼼히 확인합니다.

루트의 AGENTS.md와 CLAUDE.md는 이 배포 저장소 자체를 관리하는 지침입니다. 사용자 프로젝트에는 `framework/` 안의 진입점을 적용합니다. 이 구분은 INSTALL.md에서 AI가 처리합니다.

Markdown 지침은 실행 차단 장치가 아닙니다. 실제 테스트·CI·DB 권한은 프로젝트에 연결해야 합니다. 저장소의 자동 검사는 배포 구성과 설치 검증 도구를 확인합니다. 프로젝트의 설치 검사기는 설정 미완성·버전 혼합·파일 누락/변경·Git 공개 설정을 실제 검사합니다. 제품 코드의 품질을 보증하는 검사는 아닙니다.
